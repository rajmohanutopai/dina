# UCP Test Plan

**Status:** U0 tested and green after one independent review round (41 findings fixed). U6 built on both platforms; iOS verified on a simulator, the Android device run owed. U1–U5 and U7 scenarios listed ahead of their code.
**Companion to:** `docs/UCP_IMPLEMENTATION_PLAN.md` (the plan), whose §3.19 sets the test ladder. Interpretations and departures are in `implementation-notes.html` (UCP section).

Each scenario has an ID (`T-<milestone>-<n>`), says what must hold, and names the test that proves it. A scenario marked **pending** belongs to a milestone not yet built. Every "Tests:" line in the plan appears here under the milestone that builds it; scenarios this plan adds are marked **(added)**.

## 1. The ladder

| Rung | What | Where | Milestone |
|---|---|---|---|
| 0 | Recorded v2026-08-25 schemas served by an injected test fetcher that keeps the real `https://ucp.dev/2026-08-25/...` URLs and every authority and path check | `packages/core/__tests__/commerce/ucp/` | U1 |
| 1 | The spec's examples and response scaffolds, harvested at the pinned commit, read by Dina's readers and checked against the official `@ucp-js/sdk` 0.5.1 Zod schemas | `packages/ucp/__tests__/fixtures/spec_examples.json`, `spec_examples.test.ts`, `official_schemas.test.ts` | U0 (done) |
| 2 | An in-repo mock merchant (Fastify, REST and MCP, signing answers and webhooks, expiring idempotency keys at 24 h, completing a checkout "in the browser"), itself run against the official `conformance` suite | `packages/test-harness/src/ucp_merchant/` | U1 (read), U2 (checkout), U3 (orders) |
| 3 | A live Shopify store over MCP from the test server node, run by hand with the owner's go-ahead; never complete | manual | U1 (read), U2 (hand-off) |
| 4 | Cross-checks: Dina's RFC 9421 output against the samples' Python signer; recorded live answers against the Zod schemas | `packages/ucp/__tests__/` + a script | U2 |

**The harvest** is reproducible: `node packages/ucp/scripts/harvest_spec_examples.mjs <spec checkout>`. It reads every `json` and `http` block under `docs/specification`, indented ones inside mkdocs tabs included. It renders the `{{ ucp_version }}` macro as the site build does, strips an HTTP status or request line and headers, and unwraps MCP `result.structuredContent` (marked `binding: "mcp"`). It keeps bodies that carry `ucp`, records the spec's `<!-- ucp:example … -->` marker, and adds the response scaffolds that carry `ucp`. At tag `v2026-08-25` (`cd78fb38`) it keeps **117 examples**: 106 from the docs (22 of them MCP answers) and 11 of the spec's 23 scaffold files. The other 12 scaffolds are request scaffolds and type scaffolds without `ucp`; Dina's request bodies are checked against the SDK's request schemas instead (T-U0-80). 44 blocks that mention `ucp` do not parse: 37 use `...` placeholders, and 7 are payment-handler templates with `{handler_name}` holes or embedded-checkout examples with comments, neither of which Dina reads.
