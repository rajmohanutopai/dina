The implemented work (subject-identity resolver, scoring, record validators, forward-compat hardening) is on main — see git history. This file tracks only the remaining open questions + deferrals.

Open questions (design choices to confirm)

Open

Scoring-formula version vs resolver version. The subject-identity resolver version (RESOLVER_VERSION) and the scoring-formula version are independent in code. They are currently kept separate (a resolver bump does not force a score-formula bump). Confirm this stays decoupled.

Open

RANKING_VERSION ↔ cursor version. Bumping RANKING_VERSION requires re-emitting cursors (scoreBucket shifts under new weights). Today they move in lockstep, but the two versions are independent in code — a future maintainer might not realise a ranking bump must also bump the cursor version. Consider coupling them explicitly.

Open

audit_log_id column type. Chosen as text for forward-compat (room for non-DB audit sources, e.g. external system IDs). Could tighten to bigint with an FK to admin_audit_log.id if pure-DB audit is the only intended source.

Deferred (post-launch)

Deferred

Publish subject_id conformance vectors (conformance/vectors/subject_id.json). Deferred until a non-TS Dina-language port begins. The TS resolver unit tests + the subject-id spec doc are the de-facto vectors until there's a consumer.
