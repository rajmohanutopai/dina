Design decisions

  • Commerce protocol is a separate zero-dep package (§6) so it versions independently of the core wire protocol.
  • §9.1 arithmetic: exact BigInt rationals, one half-even rounding, integer totals, bounds fail rather than wrap.
  • Domain-separated digests, preimage dina:commerce:v1:<domain>, so no two record kinds can collide.
  • Plain validated data crosses boundaries; pure aggregates own local rules; transactional services coordinate; raw persistence unreachable from production callers.
  • §15.2b approval is a store, not a workflow task — it holds a decision the runner already made; the runner's bytes are replayed verbatim so a pack cannot revise its answer after consent.
  • Audience is judged before question: a quote addressed elsewhere is quote_fork, not quote_not_our_question.
  • Records carry digests, never signature fields — authenticity is the retained signed D2D envelope (reconcile.ts).
  • Epoch re-read: one hour, 24-hour bound after which currentEpoch() refuses. §16.2 names no interval.

Photo lanes — catalog (seller) + order (buyer) SHIPPED, LIVE-VALIDATED

Built rows-inward, deterministic spine first. Full history in git; what follows is what to remember.

Catalog lane — the load-bearing rules

  • Categories, regions and currency come from settings, never the row — a model cannot know where a seller ships. The lane's central safety claim; has its own test.
  • Unreadable cells refuse rather than guess — a nameless row was publishing its SKU as the product name; a bare pack_size defaulted to each.
  • validateCatalogItem refuses unknown keys; the key list is Record<keyof CatalogItem, true> so a forgotten field is a compile error. Reader-side ingest got its own validator — exact-keys at the reader would have vanished every higher-minor catalog, blamed on the supplier.
  • item_revision + freshness are passed in, not minted — a rebuild after a lost CAS reproduces the bytes the owner approved. Random tail, base36, letters-only (a decimal epoch tail collided with the §12.1 phone scanner live).
  • Provenance class comes from WHICH route was called, never a body field; per-field provenance derives from CATALOG_FIELD_ORIGIN — a new wire field fails to compile until someone says which side it falls on.
  • State machine created→confirmed→prepared→approved→published; only the content receipt is class-conditional, approval needs presence on EVERY class — a fully unattended publication is impossible, recorded as the owner's decision (§10 item 14).
  • approve compares the digest against Core's own snapshot — the capability holder must not approve a snapshot it named itself.
  • contentRevision counts content only — Core's bookkeeping writes must not invalidate the publication they enable. An unvalidated cast on provenance_class now fails closed to model_derived.
  • Duplicate product identities refuse at assembly — one collision broke projection, decision-keying and substitution at once; /drafts/edit was the one path back in and now refuses by name. Edits: one field per call, row-derived fields only, edited ≠ accepted.

The publication lease (dual-review rounds 2–5, 32 findings)

  • The claim carries a TOKEN, not a timestamp — age can say a claim is abandoned, never whose it is.
  • Acquisition is a conditional write — read-check-write holds in one VM and fails across two; ownership is proven by winning one UPDATE … WHERE. Parity harness holds the SQLite and in-memory rules to the same behaviour.
  • The TTL decides one question: may a NEW publication take over? It must not gate edits — a slow publication looks exactly like a dead one, so ANY claim excludes an edit and the escape is to publish.
  • Claim before the gates, released in finally — taken after fifteen validation gates, an abandoned claim was releasable by nothing, the exact wedge the TTL exists to prevent. Future-stamped claims read as abandoned (clock-skew).
  • Already-published records the LIVE pointer, validated — recording the held one beside the live CID fabricates a head that never existed.
  • The publish closure hid three defects behind userPresent: () => false — unreachable code reviews as correct; extracted to catalog_draft_publisher.ts.
  • Two checking-apparatus bugs — the mutator ledger's string stripper paired an apostrophe with a backtick hundreds of lines away (flat pattern vs nesting language, twice); the boundary guard checked files, not call sites.

Buyer lane (PC-1..9) — the load-bearing rules

  • Image ingest is a two-phase gate: bounded header parse refuses bombs undecoded (witness-proven), injected re-encoder strips EXIF, stored bytes verified on read, erasure follows the draft.
  • Extraction crosses the network only under a single-use authorization pinning provider, byte ceiling and content hashes — consumed BEFORE transmitting, re-hashed at the gate.
  • Everything extracted arrives proposed; the confirm ceremony is presence-unconditional and mints a vouch receipt committing the extraction digest.
  • Resolution egresses nothing — local token-overlap over digest-verified pages; the discovery projection has closed fields and NO text parameter, swept by test.
  • Approve is source-bound — the §2.1 binding rides inside approvalDigest; Core builds the order from its own verified quote chain and discovers the acting install itself; submit enforces generations and dispatches through ONE path with a record-first replay sweeper.
  • §5.5 divergence: exact bigint two-tier arithmetic, 13 golden vectors, badges on the approve card. §8b observability is metadata-only BY TYPE — no field a value could ride in.
  • SKU ledger: issuer-scoped, atomic claims, mint policy pack-side; claims live via publish and die via /drafts/erase.

What only live runs found

  • Presence was a hard-coded false — no seller could publish; owner_presence.ts now splits CAN (capability) from IS (5-min stamp); the verifier is the existing passphrase-unwraps-seed check, so nothing new is stored.
  • A fresh node overwrote the live pointer chain — local-only state derived sequence 1 with no swap token, a write that cannot lose; prepare now reconciles the live head and refuses an unreadable one.
  • The PDS stamps $type into stored values — readers validated the raw fetch, so a node refused its OWN epoch record every boot; stripRepoEnvelope at the read seam, fake PDS stamps like the real one.
  • Order TTL 900 > the wire's MAX_SERVICE_TTL 300 — every dispatch vanished as "sent"; §12.7 correctly ruled never_received, live-proving the loss lane.
  • Wire names are NSIDs — bare request_quote could not be declared on a listing; the supplier manifest also wanted quantity where the frozen contract says requested_quantity.
  • Hermes has no Buffer — the capture route's base64 decode threw on every real phone photo, mislabeled "not valid base64"; @scure/base now, in commerce routes and the in-process transport.
  • iPhone photos are HEIC — the picker hands original bytes; both capture screens normalize to JPEG at pick. And sharp dropped EXIF orientation without applying it, handing the vision model a sideways page; .rotate() first.
  • A write the store cannot re-read bricks the aggregate — resolveLine stored a scoped ref missing issuer_did; every later read said no_such_draft. Write-path validation now mirrors the read validator.

Traps worth remembering

  • tsc --noEmit does not typecheck __tests__. A broken test signature shows as a silently smaller suite total. Watch totals.
  • Object spreads are never excess-property checked. Only satisfies catches a misspelt wire key inside a conditional spread.
  • Backticks in SQL template comments close the literal — TS1005 at an innocent line + TS1128 at EOF is the signature. Eighth occurrence.
  • run().rowsAffected is a constant 1 in the base adapter — never use it for first-writer detection.
  • Raw NUL bytes make grep/rg skip a file silently.
  • If a fixture needs a digest, an id or a manifest, get it from the thing that makes them — six false greens from hand-built stand-ins.
  • A check never seen failing is a check of unmeasured power: revert the fix and watch the check fail before believing either.
