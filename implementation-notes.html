Design decisions

Decision P1/L1 — Registry distribution = duplicated source with a byte-identical drift gate, not a shared package.

Spec says the registry is a "shared code module" (NOT a runtime fetch — Core ingress is sync), but leaves the mechanism open. Chosen: one authored source of truth, copied verbatim where each workspace can import it locally, with a unit test asserting the copies are byte-identical (the drift gate) — same pattern the repo already uses for OpenAPI generate:check. Why: appview is a standalone workspace (not in root workspaces), so a true cross-workspace import is impossible, and a published package adds release machinery we won't add the night before launch.

Important divergence from the spec (design decision — surfaced + documented, not silently skipped):

  • L2 write-form chips → "clean by OMISSION" (stronger than chips). Investigation found the mobile review form has no dimension input at all (WriteFormState/AttestationV2Extras carry no dimensions; the form never sets record.dimensions), and the Dina-draft LLM schema (ComposeContextValues) has no dimensions field — so the draft path is pollution-proof by construction, exactly satisfying decision (b) FORBID. There is no free-text dimension surface to convert to chips. Adding chip UI now would be dead code. Instead I added two lock-in tests: (1) mobile serializeFormToV2Extras never emits a dimensions key even on a fully-populated form; (2) the merged draft state — even when a hostile inferer return tries to smuggle dimensions — produces no dimensions in the wire extras. So if a future change adds a free-text dimension field it trips the gate, forcing the canonical-chip decision back into review.
  • L4 query-side → canonical-by-construction + honest deferral. The consumer-facing half is satisfied automatically: the resolve endpoint returns averageDimensions: dimensionSummaryJson, which L3 made canonical-keyed. The query-construction half ("map user context → canonical dimension to weight a search") has no launch backend — there is no dimension-filtered search endpoint or dimension param on search_peerlens. Adding a tool param with nothing behind it would be dead code, so it's deferred (post-launch, additive) rather than stubbed. Dimensions enter ONLY via the wire ingester (attestation.ts, comparison.ts) from third-party/imported records — exactly the "non-Dina client writes straight to a PDS" case the spec flags as why the read-side net (L3) is the load-bearing defense. This makes L3, not L2, the launch-critical layer for dimensions.

The contact-gate bypass for an inbound service.response was authorized ONLY by an in-memory "requester window" (the (peerDID, queryID, capability) triple of an outbound query). That memory is lost on restart, so a legitimate response arriving after a crash/reboot was denied (no_window) — an availability bug, not a leak. Fix: a durable-backed RequesterWindowView in receive_pipeline.ts whose peek falls back to the EXISTING durable service_query workflow task (findServiceQueryTask, written by /v1/service/query before send). Same fallback at the consume site. Crucially: the durable fallback never relaxes the gate — findServiceQueryTask matches only a LIVE task (kind=service_query, status created/running, not expired, payload to_did+capability match the triple), i.e. the exact same authorization scope as the window. One-shot is preserved by the EXISTING durable completion: after acceptance the task goes terminal, so a replay finds no live task. Fail-closed on no-service / storage-fault / >1-match. +7 restart-recovery tests (accept-via-durable-task; drop on no-task/wrong-peer/wrong-capability/expired/terminal; one-shot across restart). A new audit action d2d_recv_service_accepted_durable records when auth came via the durable path. Net: the durable task also gives the restart case the replay protection the in-memory replay cache can't (it's lost on restart too) — a small security improvement, not just availability. Verified the replay-cache guard runs BEFORE the bypass block and keys on message-id, so the one-shot test (distinct ids) genuinely exercises the durable terminal-state guard, not the replay cache.
