Design decisions

  • Commerce protocol is a separate zero-dep package (§6) so it versions independently of the core wire protocol.
  • §9.1 arithmetic: exact BigInt rationals, one half-even rounding, integer totals, bounds fail rather than wrap.
  • Ten domain-separated digests, preimage dina:commerce:v1:<domain>, so no two record kinds can collide.
  • Architecture: plain validated data crosses boundaries; pure aggregates own local rules; transactional services coordinate across aggregates; raw persistence is not reachable from production callers.
  • §15.2b approval is a store, not a workflow task — a workflow approval asks to START work; this holds a decision the runner already made. The runner's bytes are held and replayed verbatim, so a pack cannot revise its answer after consent.
  • Audience is judged before question: a quote addressed elsewhere returns quote_fork, not quote_not_our_question — a different accusation.
  • Wire version stays unfrozen through Phase 0, then freezes at 1.0. Nothing is deployed and no external peer exists, so pre-release churn does not burn a major.
  • Epoch re-read: one hour, with a 24-hour bound after which currentEpoch() refuses. §16.2 names no interval — owner may want to revisit.

  • Dual review round 2 — 11 findings.   • Round 3 — 7 findings, the lease being most of them. A publication now claims the draft before the first write. The claim carries a TOKEN, not just a timestamp: age can say a claim is abandoned, never whose it is, so an overrunning publication cannot release the one that replaced it. It is persisted (so it survives a restart), released in finally (so a throwing pointer-store write does not wedge the draft for the TTL), and a claim stamped in the FUTURE reads as abandoned — a phone whose clock went backwards would otherwise hold a draft for the size of the skew, the one sequence the TTL cannot break.
  • Already-published now records the LIVE pointer. When the retry finds the head one hop ahead, recording the held pointer beside the live CID would give this node a head that never existed — sequence N's pointer under N+1's CID. The publisher validates the live record and hands it back; §10 item 8 names publication as the answer to "what did this draft publish", so a fabricated answer there is worse than none.
  • Duplicate product identities refused at assembly. Two rows resolving to one ProductRef broke three things at once: AppView refuses such a snapshot (duplicate_identity), so it would sign cleanly and project nowhere; the draft's decisions are keyed by identity, so accepting a price on one row would silently vouch for the other's; and §9.4 substitution would have two answers. Refusing during assembly removes all three by construction — no colliding pair reaches a draft, a decision map or a signature. productIdentity now has one definition, in the assembler.
  • Round 4 — 4 findings, and the lease was doing two jobs. The TTL now decides one question only: may a NEW publication take over a claim someone left? A clock can answer that safely, because the pointer write is a compare-and-swap and a duplicate attempt loses harmlessly. It must not decide "may an edit land here?" — age is a guess about whether the first publication is still running, and a publication that is merely SLOW looks exactly like a dead one. Guess wrong and the edit is taken locally while the old bytes are still on their way to the wire. So ANY claim excludes an edit, and the escape from a claim left by a dead process is to PUBLISH: a claim is only taken in publish, which needs approved, so a draft wedged this way is one whose bytes the owner already approved and whose records may already be half-written.
  • /drafts/edit was the one path back to a duplicate identity. The three ingress routes and repairRow all re-enter the assembler; editValue rewrites one item in place and saw only that item. Editing 0.product to another item's ProductRef put the collision back. It now refuses, naming the item that already holds the identity.
  • The terminal writes were undoing the token check. releaseClaim declines to clear a claim that is not ours, and the write one statement later cleared it anyway — a guard that held for an instant. Both terminal writes now take the claim from the post-await re-read.
  • The restart test never crossed SQLite. It drove two services over one in-memory repository, which proves the claim is not held in a closure and nothing about serialization. The round-trip fixture now carries a live claim, and there is a test that reopens the repository and one that reads a half-written claim as no claim at all.

The claim was taken AFTER fifteen validation gates, and an abandoned claim was cleared by publish and by nothing else — so a node that came up fenced, or held bytes that stopped validating, left a draft that could neither publish nor be edited, with no release route. The lease had built exactly the wedge its TTL exists to prevent. The claim is now taken before the gates with try/finally around everything, so any publish attempt takes an abandoned claim over and gives it back however the attempt ends.

Traps worth remembering

  • tsc --noEmit does not typecheck __tests__. A broken test signature shows as a silently smaller suite total, never a red. Watch totals.
  • Object spreads are never excess-property checked. Only satisfies catches a misspelt wire key inside a conditional spread.
  • Backticks in a SQL template literal — eighth occurrence. The signature to recognise instantly: TS1005 ',' expected in schemas.ts at a line with nothing wrong with it, plus TS1128 at the end of the file. A backtick in a SQL comment closes the literal, so the error is always far from the cause. Write identifiers in schema comments without backticks.
  • run().rowsAffected returns a constant 1 in the base adapter. Do not use it for first-writer detection.
  • Raw NUL bytes make grep/rg treat a file as binary and skip it silently.
  • Edit scripts must anchor on strings asserted to occur once before mutating.
  • If a fixture needs a digest, an id or a manifest, get it from the thing that makes them. Six false greens came from hand-built stand-ins.

The pattern, stated once

Almost every finding across these rounds was in checking apparatus I had built and believed: parity vectors that inherited my blind spots, a conformance family counted before its cases existed, a "signed" vector that was not a valid record, a probe filtering on 'failed' where the runner emits 'fail'. The divergence sweep exists because of the pattern, not any one bug, and has since found 145 disagreements.

The habit worth keeping is not "write more checks" but revert the fix and confirm the check fails. A check never seen failing is a check of unmeasured power — that is how the catalog page-count guard shipped with a test that could not fail.
