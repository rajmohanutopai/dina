Design decisions and spec interpretations

  • Separate package (§6 topology): commerce protocol versions independently of the core wire protocol; same conventions (nullable-error validators, injected Sha256Fn, frozen vectors, dep-hygiene gate — src/ imports relative paths only). canonicalJson is a deliberate copy of @dina/protocol's JCS subset; frozen vectors on both sides turn copy drift into a test failure.
  • §9.1 "exact under the declared unit conversion" read as: the CONVERSION must be exact (kg/g, l/ml, same-code); the quantity/priceBasis ratio may be fractional — the integer-quotient reading would falsify the spec's own "per-unit pricing always does" clause. Case↔each is refused, never guessed.
  • Choices the spec left open (flagged below for confirmation): unit vocabulary v1 = each/case/pallet/g/kg/ml/l, custom unit codes rejected; bounds = 15-digit minor units / 12-digit quantity integers; currency validated as shape only (no ISO table pin); termsDigest input = charges + estimates + paymentTerms + validUntil; reasonCode = open bounded snake_case vocabulary; timestamps = canonical ISO UTC (Z, fraction absent or 3 digits); totals reject an intermediate-negative running sum.
  • Deviation from house export policy: operational commerce tables (heads, counters, order refs, watermarks) ARE exported — §16.2 requires it; restoring receipts without them would reset counters or fork heads. The stale-backup residual is fenced by the commerce epoch, not by exclusion.
  • Partial quotes are legal (a quote need not answer every request line, §19); all-or-none binds ORDERS to quotes. Genesis status state is DERIVED from the recorded acknowledgement — callers cannot claim a different resolving event.
  • host_operations enters the scope hash only when non-empty, so every pre-commerce manifest and frozen digest vector keeps its hash while widening still forces re-consent (absent == empty == no brokered authority).

Owner decisions (both previously blocking, now settled)

  1. Post-restore quote capacity (X-10). §16.2 says admission against a restore-voided quote returns quote_superseded with “a freshly signed head at the new epoch”, and separately that “capacity is never resurrected from a backup”. It never says what capacity that fresh head carries — and that is a money question. Decision: Core never synthesizes a replacement. It holds no commercial authority (Kernel-not-Platform), and it cannot know how much of the original allowance was really consumed: the backup’s use counter is precisely the number a stale restore makes untrustworthy. A supplier-side seam owns the re-offer. With no seam wired, admission refuses with quote_voided and no digest — naming the voided head would have the buyer re-approve forever against something that can never go live again. This is a deliberate, recorded deviation from the spec’s literal wording: the spec asks Core to do something Core is not permitted to do.

Architecture decision — why a refactor, not more patches

Four review rounds kept finding second-order breaks: a correct, tested fix in one place broke a rule enforced in another. Twice the damage came from my own remediation — the §11.2 ownership gate silently disabled §16.2 disaster recovery, and persisting valid_until supplied the last ingredient for reviving an expired pre-backup quote family. That is not bad luck four times; it is a structural signal.

The smells, measured:

ruleplaces enforcing itowner
“capacity is never resurrected from a backup”4+none
“does this order exist”14 call sitesnone
“wire records are snake_case”12 as castsconvention

Named: shotgun surgery (one idea, many edit sites — the cost of a change tracks how many sites you remember, and I remembered three of four); anemic domain model (rows plus discipline, so a quote family cannot refuse an illegal operation because it is not a thing); lying casts (the compiler told not to look at exactly the boundary that needed checking); and a non-exhaustive switch over parsed JSON (the type system asserting a fact about untrusted data). The tests were the only net holding these together, and seven of them turned out to hold nothing.

Recorded because I got the reasoning wrong first: I declined the deeper fix partly because it was a day’s work and would invalidate four review rounds. Neither is a reason. Reviews are cheap to re-run; wrong structure is not cheap to live with. The only legitimate constraint is avoiding rigidity.

Agreed design (refined against a Codex review of the proposal)

Plain validated data crosses boundaries. Pure domain aggregates own local state rules. Transactional application services coordinate cross-aggregate changes. Raw persistence primitives are not available to production callers.

Four corrections to my first proposal, all accepted:

  • Uniqueness across (buyer_did, purchase_order_id) and (buyer_did, idempotency_key) is a database invariant. One CommerceOrder cannot own a rule about all orders.
  • Deciding an order and settling its quote hold spans two aggregates plus receipts. It belongs to a transactional application service, not to CommerceOrder — my version would have pushed quote knowledge into the order.
  • Typed results, not throws, for business outcomes. Expired, consumed, superseded and illegal-transition are normal results that travel to the buyer as wire reason_codes. Corruption and impossible state (a failed settlement inside a committed decision; a head row whose receipt is missing) throw and roll back. Conflating the two is arguably what produced the ignored settleUse boolean.
  • Hiding the repositories is the whole point. QuoteFamily.advance() is worthless while casAdvanceHead() stays callable — the next call site simply bypasses it. Success is measured by a grep returning empty, not by a passing test.

One discipline added on top: application services coordinate and persist, and must not re-derive aggregate rules. A service that re-checks epoch or capacity “to be safe” has scattered the rule again and become a god-object with extra steps.

Wire types stay plain serialisable data with validators — they are hashed byte-exactly, frozen in conformance vectors, and must be reproducible by a Go/Rust/Swift port. Turning them into classes would fight both. No unit-of-work ceremony over the existing synchronous DatabaseAdapter and explicit TxRunner: that is rigidity, not correctness.

Decisions worth knowing:

  • Refusals are values; corruption throws. Expired, consumed, superseded, voided, stale-epoch and duplicate are ordinary outcomes that become wire reason_codes, so they are returned. A settlement CAS that cannot fail failing, or a head row that will not read back after being written, throws — those mean the ledger and the order references disagree, and committing half a decision is worse than aborting.
  • The aggregate does not re-check the protocol verifier. Revision numbering, audience, request binding, in-chain epoch regression and immutable max_uses belong to verifyQuoteRevisionExtends. My first version re-implemented two of them locally — the same scattering, one layer down — and answered with a vaguer message than the real one. It now calls the verifier and carries its sentence through in a detail field. Only one rule is the aggregate's alone: epoch monotonicity, which compares the head to Core's restore history and is invisible to a verifier that only sees two revisions.
  • detail is operator text, never wire text. The buyer-facing reason_code is derived from the refusal name alone, through a total Record<QuoteRefusal, string> — so a new refusal cannot reach a counterparty unhandled. stale_epoch maps to quote_voided: to the buyer they mean the same thing, this family is gone.
  • Duplicate is decided before capacity. Capacity-first told a caller retrying its own order that the quote was consumed — by the caller's own hold.
  • hold() checks expiry itself rather than trusting that admits() ran first. An aggregate whose rules only hold when methods are called in the right order is the discipline this refactor exists to remove. It judges against the head's window, which the family keeps current; admits() judges the record the order names, which may be an honoured superseded revision with a different deadline.
  • An instance is a one-transaction snapshot of the head row. Stated in the class doc because nothing in the type system says so.

Debt this leaves, recorded rather than hidden: the restore sweep still calls voidUnexpired, which by construction cannot see an already-expired family. It is kept because the restore is an event that must leave a receipt with a real count — the fence itself is now epoch monotonicity, which needs no sweep and cannot miss a row.

Verification: nine mutations, each asserting its anchor exists before removing it — a silent no-op mutation reads as a passing suite. All nine went red. Two (stale_epoch at admission, settlement rollback) were caught only by the aggregate's own unit tests until cross-layer tests were added; both now fail in two suites. Grep confirms no production file outside the aggregate names registerHead, casAdvanceHead, holdUse, settleUse, voidUnexpired or activeUseCount. Gate: tsc clean, eslint clean, core 6,271 passing.

Two false-green tests were caught during this item. The first asserted the validity window advanced with the head without ever reading it — fixed by exposing validUntil and asserting it. The second asserted duplicate_use on a single-use quote, where capacity is exhausted by the first hold, so the refusal it named was unreachable.

Dual review — four rounds

Two independent reviewers: a Claude continuity subagent and Codex via the openai-codex plugin. R1 8+17, R2 5+12, R3 7+15, R4 6+15. No version has yet had both PASS.

The counts did not fall monotonically, and the reason matters: R1 reviewed the original code; R2 mostly reviewed the snake_case conversion R1 demanded (1,400 renamed sites); R3 mostly reviewed R2’s fixes and their tests; R4 reviewed the wire change and the round-3 fixes. Each round found a different, shallower layer rather than the same defects recurring.

R4 produced no reviewer disagreements — the first round with none, because the scope ruling above was given to both as a frozen rubric. Four findings were flagged independently by both. Where severities differed the higher was taken.

Test quality was the dominant recurring theme. Seven tests were caught passing for the wrong reason: a missing verifyHeldEvidence default; hand-built acknowledgements rejected before the branch under test; a guarded if that asserted nothing; receipts.put ignoring conflicts so in-place corruption silently no-oped; admission returning reserved with no acknowledgement; an assertion comparing a value to itself; and an unwrapped evidence fixture. Every guard added in rounds 2–4 is now mutation-verified — reintroduce the defect (asserting the code is present first), watch the test go red, restore. Two mutations were themselves caught as no-ops by that assertion.

Traps worth remembering

  • tsc --noEmit does not typecheck __tests__ in either package. A broken test signature shows up as a silently smaller suite total, never as a red. Watch totals, not failures.
  • Object spreads are never excess-property checked, whatever the target annotation. Only satisfies catches a misspelt wire key inside a conditional spread. Annotating the const achieves nothing — I tried it and the misspelling still compiled.
  • Raw NUL bytes in three source files made grep/rg treat them as binary and skip them silently. Replaced with escapes. Any audit that relies on grep was blind to those files.
  • Edit scripts must anchor on strings that occur once, asserted before mutating. A loose pattern matched the wrong if (head.voided) branch — there are two — and deleted a method.
