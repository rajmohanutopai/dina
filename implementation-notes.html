Plan (doc §6 order)

  • A. Research loop — product-search tool in the agentic loop; consumer caller for cross-supplier search + rank; trust producer (subject_scores → trustBp); consumer compare screen; recommend + hand-off; preference matching. Building first.
  • B. Kernel/plugin split — extract the money engine (module + runtime + repository split, §5.B1); keep the catalog kernel-side.
  • C. Plugin substrate — repo-proof verifier in production (injected net adapter); general install/consent/uninstall UI.
  • D. Country packs — India/USA connectors, language/PII, review feeds, notification channel.

Design decisions

  • Core's transport does not know what a khata document is (§5.B1) — d2d/trade_ingress_seam.ts is a registry the money engine registers into, not an import the pipeline makes. A seam rather than a parameter because the pipeline is reached from four places and none of them is a composition root; threading a handler through all four would put a money-shaped argument in four signatures with no other reason to mention money.
  • An imported review is not testimony, and the code says so in four places (D4) — it carries a fixed weight rather than its publisher's trust; it is capped as a corpus so volume cannot bury the people who actually dealt with a supplier; it never counts toward confidence; and it creates no trust edge. Each is a separate hole, and closing three of four would still let a market be bootstrapped into reputation.
  • Provenance is checked against this node's agreements, not the record's word — a source block is admitted only from a registered feed published by that feed's own DID. The feed's NAME and HOMEPAGE come from the registry at render, never from the record: a publisher naming itself in its own records would be naming itself in Dina's chrome.
  • A plugin card is a TEMPLATE, not a payload (§15.6) — the manifest declares the layout and the literal words, the result fills slots. A runner cannot author a layout per answer, and a publisher cannot name a field the runner will never send (the manifest validator refuses an undeclared slot). A slot is a whole string of one identifier in braces: partial interpolation truncates the sentence around an over-long value and re-enters substitution on a value carrying its own braces, and the block vocabulary already separates label from value, so nothing needs fragments.
  • Only blocks survive an untrusted plugin render — the CardSpec frame (sourceLabel, generatedAt, expiresAt, ttlSeconds) draws a source line and an "as of" stamp, which is a claim about provenance and freshness. §15.6 says system labels are Dina-owned, so a publisher writing "Official GST record" into that slot would be minting trust UI by another name. link and media go too (§11: no URLs); map stays, because the renderer builds its deep link client-side from coordinates and the destination is a maps app rather than a page a publisher chose.
  • Plugin context is a Dina-owned TABLE, not a manifest request (§11 point 3) — CONTEXT_TEMPLATES keys fields by (category, action class) and CONVERTS each value to its declared class rather than only filtering: a date_class slot turns a timestamp into this_week, so a buggy or hostile source cannot push an instant through it. Every projected value is a string, which is what keeps a raw vault row out of a payload structurally rather than by inspection. A category with no template, or an action class the table does not name, projects nothing.
  • The invocation carries a SUBJECT, never a context — {contactDid?, documentDigest?}. Naming who a task is about is not push-context: Core still decides which facts about them travel. The old context?: unknown argument is gone from invokeToolCapability and neither route accepts one.
  • A projected value is DROPPED, never substituted — each one is re-scanned with regulatedContentIn, the same detector the envelope backstop uses, so the producer cannot build a context the builder would refuse. A GSTIN travels (its inner PAN is not at a word boundary); a bare PAN registration does not. Substituting a placeholder would hand a runner a corrupted legal name and call it scrubbed.
  • Persona tiers derive from the declared scope, with the injected policy as an override — the strictest reading of an unrecognised persona is "locked". Defaults that read false are how a gate ends up wired to a constant; this one now fails toward the clamp.
  • Catalog reads for research, not live RFQ (§7.1) — the consumer path is money-free, so it ranks PUBLISHED catalog offers (prices already in commerce_catalog_products) rather than fanning out live signed-quote RFQs; the RFQ/quote lane stays for the close. Open for owner confirm.
  • Catalog→Offer bridge — rankOffers (offer_ranking.ts) is quote-shaped (needs quoteId, expiresAt); a catalog offer has neither. The bridge maps a catalog product row to an Offer with a stable synthetic id and a catalog-freshness window as expiresAt, reusing the §13.2 filters + §13.3/4 scoring on catalog data. Confirmed the clean path (not a catalog-specific ranker).
  • Brain-local orchestration — the research tool runs in the Brain over pure @dina/core functions plus a direct AppView fetch (the search_peerlens precedent); no new CoreClient method, and Core makes no external call.
  • Trust split (§7.2) — seller-DID trust → Offer.trustBp (ranked, 1500bp); product-subject reviews are DESIGNED to feed the card's evidence param (shown, not ranked). Zero change to offer_ranking's weights. Deferred (open §5.A3/§7.2): the consumer loop does not yet fetch product-subject subject_scores nor pass evidence, so the card's Evidence line reads "none recorded" today. Seller trust IS wired; product-review evidence is the honest remainder.
  • Numeric seller trust via getProfile — the ranker needs a number (overallTrustScore 0..1); resolveTrust/searchTrust only return a trust-LEVEL string, so the Brain client gained getProfile. A null profile or null score means no trust input, never scored as zero (§13.4).
  • get accepts repeated query params — widened to Record<string, string | string[]> to honour the AppView queryList contract (?identifier=a&identifier=b). Backward-compatible: single-value callers are unchanged.
  • Card surfacing rides a new commerce_comparison lifecycle, not the service-query path (§5.A4/A5). A tool-result card does not reach the mobile UI on its own — the agentic loop only serialises tool results back to the LLM. So the coordinator lifts the search_products card onto answer.commerceCard (a validated CardSpec) in translateLoopResult, and the chat bridge posts it as a commerce_comparison lifecycle message the mobile draws through the existing SafeCardRenderer. The service-query path was deliberately NOT reused — it is keyed on a workflow task and driven by an async D2D event this synchronous card has none of. Card-first ordering (card, then the loop's narrative). Where-to-buy links are https-only (validateCardSpec drops at:// and private hosts), so a supplier's service URI shows as a named line until catalogs carry a real source page — honest today, richer as the wire grows.
  • Routing is built; preference-weighting is emergent but committed through a tool (§5.A1/A6, superseding the Iter 5 note). The Iter 5 decision — "the model picks search_products by its tool description; a products classifier source is deferred" — failed the real-model run (Iter 30: the system prompt's source legend gated the loop to PeerLens). Routing now follows §5.A1 as written: a products intent source, the ask prompt's legend and tool map, a planner preferences check. The weighing stays the model's (no per-scenario rules) over offers that carry readable prices and the owner's own record of each seller; the decision is then committed with recommend_offer so the card the owner sees agrees with the words.
  • Casual-consumer requirements — a research query rarely names a quantity/currency, so the tool defaults quantity to one unit and anchors the compare currency on the first priced candidate; off-currency offers are REPORTED (currency_mismatch), never converted (§9.1). Region is enforced by AppView discovery, so it is NOT re-applied as a rank filter (the wire region and the offer's scheme:value form differ).

Deviations

  • availableQuantity = the requested quantity in the bridge — a catalog carries no live stock (FR-A7) and a listing IS an offer to supply, so this neutralizes the §13.2 stock filter honestly rather than special-casing the ranker.

Tradeoffs

  • The review-feed registry ships empty, so the whole import path refuses by default — which reads like dead code and is not: the refusal is what stops a rogue node claiming a source's name, and the admission path is composed by an operator at boot (setReviewFeedRegistry) with whatever their terms permit. "Usage terms the Pull Economy allows" is the actual difficulty of D4, and it is a contract decision this repo cannot make on anyone's behalf.
  • subjectGet.reviewCount now means TESTIMONY, matching the roster it sits above — a count that included imports would say "5 reviewers" over four rendered rows. resolve.reviewCount keeps meaning the total, because that response has no roster to disagree with; both now carry the peer/imported split explicitly.
  • card_snapshot is pinned but NOT claim-checked — schema_snapshot is verified at claim because a result schema is consent; card lives in the presentation hash, and §14 says a presentation change never blocks work in flight. So a card rewritten mid-flight lands in Activity and the in-flight answer still renders in the shape the owner approved.
  • Three context categories, not eight — the country packs declare payment, delivery, tax, tax_filing and invoice as well, and those project NOTHING today: the facts behind them ride the rail's params, where the egress gate reads every one. A template with no store to read would be dead code pretending to be a policy. The projection reports each such category as unsourced so the silence is visible rather than passing for "there was nothing to send".
  • The country-pack manifests gained max_context_items (and address/business_registry where a document prints them). An absent ceiling means ZERO, so without this the packs would have received an empty projection and a pile of cap refusals. For an already-installed pack this is a scope widening, which the update path answers with a re-consent card — the designed behaviour, worth knowing before the next dev-node boot.
  • Never-expires rendering — comparison_card renders a far-future (year ≥ 9000) validity as "no stated expiry" by a local heuristic, to stay decoupled from catalog_offers' sentinel constant. Importing the constant would couple the generic card to the catalog bridge; kept them independent.

Open questions

  • B1's package move: is packages/commerce-pack one package or two (buyer / supplier)? The money STORES are shared — one khata serves both sides — so one package holding the engine, with the two reference manifests staying where they are, looks right; worth a decision before the move rather than during it.
  • Should /v1/plugins/tool-invoke (Brain) be able to name a subject? Today it cannot, so a Brain-routed ask projects only subject-free facts (the owner's own business identity). Letting the model name a counterparty would widen what a projection reaches on the model's say-so; the rails, which know the counterparty for certain, name it instead.
  • Reuse depth of procurement_service for a money-free read path (§7.6) — its fan-out/rank/evidence sequence assumes live quotes; the research path may want a lighter compose that shares only the ranking.
  • Trust weighting (§7.2) — one trustBp folding product-review + seller trust, or two separate factors.

Traps worth remembering

  • tsc --noEmit does not typecheck __tests__. A broken test signature shows as a silently smaller suite total. Watch totals.
  • Object spreads are never excess-property checked. Only satisfies catches a misspelt wire key inside a conditional spread.
  • Backticks in SQL template comments close the literal — TS1005 at an innocent line + TS1128 at EOF is the signature.
  • run().rowsAffected is a constant 1 in the base adapter — never use it for first-writer detection.
  • Raw NUL bytes make grep/rg skip a file silently.
  • If a fixture needs a digest, an id or a manifest, get it from the thing that makes them — six false greens from hand-built stand-ins.
  • A check never seen failing is a check of unmeasured power: revert the fix and watch the check fail before believing either.
