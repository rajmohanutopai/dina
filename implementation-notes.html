Change Passphrase (uncommitted)

Settings → Security → Change passphrase (2026-06-17). The capability existed only as dead code (useSecurity.doChangePassphrase + the changePassphrase crypto primitive) but was never wired to a screen and never persisted. Built the durable path + UI. mobile: new service 10 tests, new screen 5 tests, legacy useSecurity suite still green (39 total); tsc clean.

Decisions / invariants
  • A passphrase only wraps the master seed (Argon2id KEK → AES-256-GCM). Changing it is a re-wrap of the SAME seed, so every persona DEK (HKDF-derived from the seed) is untouched and all vault data keeps decrypting — no content re-encryption, no migration. The 24-word recovery phrase (which encodes the seed, not the passphrase) is unchanged.
  • Durable order (the bug the legacy hook had): load wrapped seed → re-wrap (wrong current passphrase fails the GCM tag here, writes NOTHING) → saveWrappedSeed (the unlock source of truth) → then refresh the auto-unlock cache. Seed-first so the new passphrase is live even if the cache write fails.
  • "Unlock automatically" users get saveAutoPassphrase(new) so silent boot keeps working; manual-mode users get nothing cached. The cache refresh is best-effort (try/caught): a failure can't report the change as failed — worst case the gate falls back to a one-time manual prompt and re-caches.
  • Generic wrong-passphrase surface ("That current passphrase is incorrect.") — no oracle about which step failed, matching the recovery-phrase + unlock gates.
Implementation
  • New durable service apps/mobile/src/services/change_passphrase.ts (changeVaultPassphrase) over the real wrapped_seed_store + startup_preferences — NOT the in-memory useSecurity hook (which is left in place for its tests + reused pure helpers validatePassphrase/getPassphraseStrength, now annotated as legacy).
  • New screen apps/mobile/app/change-passphrase.tsx (current/new/confirm via PassphraseField + strength meter + success state) registered as a drill-down route in _layout.tsx; row added to Settings → SECURITY under "View recovery phrase".
  • Client-side guards (empty current, new≠confirm) short-circuit before the service; the service re-validates + rejects no-op (new == current) before any keychain touch.
Not yet usable in the running web build
  • The Home-Node-Lite web app serves a pre-built bundle (apps/home-node-lite/web/dist, last exported 2026-06-15) — the new row won't appear there until cd apps/mobile && npm run web:export rebuilds it. Instant on the iOS dev-client sim via Metro hot reload.
